# 稳定性、可靠性与 UI 细节改进计划

日期：2026-09-20。基于 `dcad484`（1.0.82）、待合并的 `77d0a3e` / `40ce6f9`，以及本轮代码检查。

## 判断与范围

建议进入连续的小版本质量改进阶段。最近的工作已经集中于终端历史、Ghostty 兼容性、worktree 删除刷新、Git 首次加载和侧边栏；下一步应把这些路径的异常恢复与回归验证补齐。

保留 AppKit + SwiftUI + Ghostty 架构，每批围绕可复现的问题交付。暂不扩展 agent 平台、编辑器体系或其他大功能，也不为统一风格而全面重构状态管理。

## 后续批次

### 第一批：保护用户的工作状态

- 文件编辑：保存前检测磁盘内容变化；切换文件、关闭 sheet 时明确处理未保存修改。现有直接写入路径缺少外部修改冲突保护，优先补齐。
- 终端历史：验证正常退出、强退、关闭 pane/tab/workspace、禁用设置的清理行为；记录多 pane 的定时采集耗时。当前在主线程采集且同步等待磁盘操作，先测量再决定异步改动。
- worktree：连续切换、外部删除、删除失败与刷新重叠时，验证选择、终端与侧边栏一致；保持 pending-removal 的现有保护。

验收：失败不丢编辑、不误报成功；恢复内容可读但不会在新 shell 执行；旧异步结果不覆盖当前上下文。

### 第二批：高频 UI 操作的可预测性

- 侧边栏：窄宽度、长名称、空分组、搜索后选择、展开折叠、多选、右键和拖动排序。
- 终端：中文输入法组合输入、菜单快捷键冲突、tab/pane 切换后的焦点、缩放后光标和滚动位置。
- Diff / History：首次打开、快速切换、刷新、失败重试、无结果、超大内容的状态一致性；逐步统一既有提示文案及无障碍标签。
- 每个 UI 改动附手工 smoke 记录；只在涉及状态转换时补逻辑测试，避免恢复依赖 Combine 调度时机的脆弱测试。

验收：浅色/深色、键盘操作和窄窗口中均能辨认当前选择、加载状态及下一步操作。

### 第三批：有证据的性能优化

- 固定小/大仓库和多 pane 场景，记录首次打开、切换、刷新耗时及空闲 CPU、内存。
- 优先检查终端历史采集、频繁发布状态、重复 Git 请求和后台任务取消传播。
- 对比修改前后的同一场景；没有性能数据支持的重构不进入补丁版本。

## 发布门槛

1. 先合并历史改动 PR，再合并本轮修复 PR；各自当前提交的 GitHub Actions 全部通过。
2. 本地运行 `xcodebuild -project Liney.xcodeproj -scheme Liney -configuration Debug -destination 'platform=macOS,arch=arm64' build test`。
3. 运行 `compatibility-smoke` 验证真实 Ghostty 创建、缩放、读取、历史持久化和销毁。
4. 手工 smoke 覆盖保存失败、预览/历史错误重试、分组与焦点；未执行的项目明确记录，不以单元测试代替。
5. 按 `RELEASING.md` 使用现有签名、公证、Sparkle 和 Homebrew 流程。凭据缺失时停在已验证的提交，不跳过签名或公证。
6. 版本说明围绕修复的用户体验，发布后验证 GitHub 资产、appcast 版本与 Homebrew 校验信息一致。

## 检查边界

本轮为近期提交和高风险路径的源代码审查与回归验证，不等于所有功能均已实机验证。远程 SSH、长时间运行、睡眠唤醒和完整自动更新安装链路需要单独的场景验证。以上后续批次中未复现的性能与交互问题是待验证项，不作为已确认缺陷。
